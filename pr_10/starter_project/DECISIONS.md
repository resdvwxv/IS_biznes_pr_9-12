# DECISIONS

## Решение 1. Стратегии доставки вместо условной логики в DeliveryService

Расчёт вынесен в реализации интерфейса `DeliveryPolicy`: `StandardCourierPolicy`,
`ExpressPolicy`, `PickupPolicy`, `CargoPolicy`. `DeliveryService` не содержит
цепочек `if`/`switch` по способу доставки: он получает политику из
`DeliveryPolicyFactory` и вызывает `supports` и `calculateCost` полиморфно.

`DeliveryPolicyFactory` отвечает только за выбор реализации по `DeliveryType`
и не содержит формул расчёта стоимости.

## Решение 2. Вариант 6: ограничение по весу 35 кг для CARGO

Для варианта 6 добавлен четвёртый способ доставки `CARGO`. Ограничение по весу
сосредоточено в одном месте - константе `CargoPolicy.MAX_WEIGHT_KG = 35.0`.
Граница включительная: вес ровно `35.0 кг` разрешён, `35.0001 кг` - запрещён.

Проверка входных данных вынесена в компактный конструктор `DeliveryRequest`:
тип обязателен, расстояние `>= 0`, вес `> 0`, сумма заказа `>= 0`.
Невозможность доставки выражается исключением `DeliveryUnavailableException`.
